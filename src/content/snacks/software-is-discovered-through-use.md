A request for an application rarely contains enough information to determine the finished product. It may describe the purpose while leaving out permissions, edge cases, terminology, data relationships and the sequence that makes the workflow feel correct. Some of those details are unknown until an early version exists.

Use exposes what the original description could not. A screen feels awkward. A missing state appears. A sensible process fails when it meets real work. Building a desk or piece of furniture follows a similar pattern. The object may need to be used, rebuilt and used again before the spacing and movement feel right. Software develops through the same repeated contact between intention and result.

The builder’s mental model changes alongside the product. An agent can implement an instruction correctly while the instruction itself turns out to be poor. Close review catches that discovery before more features are built on top of it. Human attention therefore does more than approve generated work. It carries the lived problem, recognises when the system does not fit and revises the definition of the product as new knowledge appears.
