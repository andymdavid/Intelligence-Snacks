# Graph exploration

Build and validate with bun install --frozen-lockfile, bun run graph:test, and bun run build. Build includes graph quality gates before and after Astro: canonical destinations, endpoint identities, accepted graph states, one knowledge revision per episode, matching topic revisions, evidence availability, complete built index, and published output paths. The source snapshot hash is emitted with the counts.

The archive index is server-rendered and contains every public node. The visual map is a bounded overview balanced across episodes; selecting any node builds its immediate neighborhood. The details panel lists all incoming/outgoing connections even if the visual projection is limited. Search, kind, episode, topic, and focused node are encoded in the URL. Canonical published files supply Snack copy and URLs. Editorial-only Episode 64 drafts are excluded and the seven actual published Snacks are present under their own identities. No draft-to-article equivalence was invented.

Knowledge evidence loads from /graph/details.json only after selection. Source links use deterministic transcript-turn anchors and open the transcript reader. The page works when WebGL or the rendering bundle fails. The complete content index also works without JavaScript. Reduced-motion users get a static initial layout and a freeze control is available. The overview does not use raw degree as semantic importance.

src/data/graph-concepts.json contains the initial reviewed graph-memory and agent-harness groupings, marked agent-editorial-review by Lara. They express topic membership, not equivalent claims. A nonempty reviewed Studio conceptRegistry in a new export takes precedence. Unreviewed suggestions do not publish. Use proposeConceptMentions to propose overlaps, then inspect the cited source before accepting. Reject semantic/causal relations that only share keywords. Stable concept IDs are independent of extraction UUIDs; changing extraction identities requires explicitly remapping source mentions, enforced by the build.

Knowledge mix percentages mean primary classified-word share, with total coverage shown separately. They do not measure importance, audience interest, or speaking time. Topic filters retrieve ideas and Snacks from the episodes that contain the topic; this is episode-level retrieval, not a claim that every returned node belongs to the topic.

The document emits local CustomEvent('snack-graph') events for selection, source/evidence opens, filters, cross-episode navigation, and renderer fallback. Payloads contain action, kind, and episode number; they omit search text, identity and full URLs. No new third-party tracking or persistence is enabled. Connect events to an approved analytics collector to measure adoption after release.

Evaluate three reader tasks after release: find a recurring idea in another episode; understand a contradiction from its explanation and source; navigate from a Snack to supporting evidence. Record completion and time, zero-result searches, graph-to-content/source transitions, and cross-episode discovery. Audit semantic precision with explicit labels: supported, ambiguous, unsupported, wrong direction, or wrong attribution. Model confidence is not an empirically calibrated probability. The two initial groups were agent-reviewed, not a representative precision benchmark or human usability study.

Local Chromium evidence: renderer starts without page errors, all 670 nodes are indexed, search finds late-episode knowledge, evidence is deferred, keyboard selection loads excerpts, transcript anchors auto-open, graph-memory exposes three different episodes, URL focus survives reload, mobile width 390 has no overflow, rendering-bundle failure retains evidence/search, no-JavaScript content links work, reduced motion is honored. Local navigation timings are development evidence, not real-user Core Web Vitals.
